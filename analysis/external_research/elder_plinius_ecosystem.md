## 1. ST3GG — the steganography toolkit (deep dive)

Reviewed at commit `35f8b2b8529a74091c97ce622ee0cbf1ae3bd260`
(2026-06-15). The source was inspected from a partial clone outside this MIT
tree; that upstream revision is AGPL-3.0.

### What it is

A "hide anything in any file" toolkit: 100+ encoding techniques across
images, audio, text/Unicode, documents, archives, network packets, and code
files. Ships as a browser-only static site, a Python CLI/TUI/WebUI, an MCP
server, and a `stegg` PyPI package. Every technique encodes and decodes; the
analysis side ("ALLSIGHT") has 20+ detection functions.

### Mechanisms catalog (relevant to this repo)

- **LSB image stego engine** (`steg_core.py`, ~1300 lines): vectorized numpy,
  15 channel presets × 1-8 bits/channel, 4 embedding strategies (sequential,
  interleaved, spread, randomized), a **self-describing 32-byte header** with
  magic bytes + serialized config + CRC32, auto-detect of parameters on
  decode. Password-derived magic (HMAC) so the header is undetectable without
  the password.
- **SPECTER channel cipher**: bits hop across color channels in a pattern that
  serves as the key (manual or password-derived). LSB or DCT embedding.
- **Ghost mode**: AES-256-GCM + seeded Fisher-Yates bit scrambling + 50% noise
  decoys.
- **Matryoshka mode**: recursive nesting up to 11 layers; smart decoder
  auto-unwraps on PNG magic bytes.
- **F5 / DCT modes**: JPEG-coefficient embedding claimed to survive social
  media recompression.
- **Text/Unicode techniques**: zero-width chars, invisible ink (Unicode tag
  block), homoglyphs, variation selectors, combining diacritics, confusable
  whitespace, whitespace (space/tab) encoding, emoji substitution,
  capitalization encoding.
- **Network techniques**: DNS tunneling, ICMP payload, TCP ISN/timestamp
  channels, HTTP header smuggling.
- **Document/archive techniques**: PDF metadata/XMP/post-EOF, HTML comments
  and data attributes, XML CDATA/PI/namespace, JSON key-ordering, ZIP/TAR
  comments and extra fields, SQLite hidden tables, code comments in many
  languages.
- **Analysis** (`analysis_tools.py`): chi-square, bit-plane entropy, PVD,
  histogram-shift, multi-bit LSB, PNG chunk parsing, EXIF, signature scans,
  Unicode-stego detection, whitespace detection. Registered as a 48-tool
  registry with `--full` sweeping.

### Engineering patterns worth borrowing (independently)

1. **Self-describing headers**: embed magic + config + checksum in the carrier
   so decode auto-detects parameters. This is directly applicable to
   agent-stego's tool-call channels, where the decoder currently must know the
   channel mode and table in advance.
2. **Exhaustive detection registry**: a uniform "try every known technique"
   interface, used for both detection and decode auto-detection. This is the
   pattern behind `exhaustive_decode` in this repo's new tripartite harness.
3. **Agent-facing CLI/skill/MCP**: subprocess CLI with JSON output (zero
   context cost), a `SKILL.md` for harness-agnostic agents, and an MCP server.
   agent-stego has no agent-facing interface today.
4. **Example library as test corpus**: 100+ pre-encoded example files, each
   with a known payload, regenerated by a script. agent-stego's detection arm
   would benefit from a synthetic tool-trace corpus with ground truth.
5. **Honest capacity accounting**: the README states plain LSB is statistically
   detectable and that capacity claims depend on exact channel/bit settings.
   This matches the integrity culture this repo is already rebuilding.

### ST3GG's AI-agent surface (most relevant section)

- "Reveal & Conceal" AI agent powered by OpenRouter that tests every decode
  method or hides data via an optimal method.
- Agent stego use cases listed: prompt injection via images, agent data
  exfiltration through generated images, covert agent channels through shared
  tool-context files, output watermarking, content-filter bypass, multimodal
  poisoning.

The overlap with agent-stego is at the *tool-context file carrier*: files
agents legitimately read/write can carry hidden payloads (comments, metadata,
whitespace). That is an unexplored surface in this repo's charter map (the
"files, metadata, structured documents" row is marked known-carrier-class but
agent-interactions unexplored).

## 2. GLOSSOPETRAE — the closest prior work (deep dive)

"Procedural xenolinguistics": generates procedural conlangs, measures how
frontier LLMs acquire them, and uses the acquisition/tokenizer asymmetries as
covert channels. Its four pillars:

1. **Generation**: procedural conlang engine (phonology → writing systems →
   audio → evolution → even programming languages), 500/500 languages.
2. **Acquisition**: LLMs acquire a novel language in-context — 0% at K=0,
   95-100% at K=8, a sharp universal cliff across 9 frontier models.
3. **The Decoupling**: making a language *less* human-readable *increases*
   model usability (L0-hard: Opus 20%, GPT 53%; L3-hard: Opus 97%, GPT 100%).
4. **Covert channels**: three-role experiments (sender/receiver/monitor) with
   graded payloads.

### The covert-channel findings (as published)

- **Tokenizer blind-spot channels**: hide payloads in characters that one
  model's tokenizer deletes but another's keeps. Tag characters (U+E0000
  block): Haiku→GPT delivers R=100%, monitor catches M=0% (n=30, McNemar
  p<10⁻⁷). PUA channel: Gemini→Haiku R=93%, M=0%. The monitor is "blind, not
  dumb": it catches 0% even when handed the exact decode key, because the
  carrier never enters its token stream.
- **12-model blind-spot map**: Anthropic models blind to 10 carrier classes
  each (worst), OpenAI 2, Qwen/GLM 1-2, six families zero. 255 exploitable
  channel-instances across 49/66 model pairs; richest at the cross-vendor
  GPT↔Claude boundary — exactly the "monitor with a different vendor" setup.
- **The Detection Flip**: tokenizer-blind monitor Youden's J=0 (chance),
  sighted monitor J=1.0. Same channel, opposite outcome, decided entirely by
  the tokenizer.
- **Semantic steganography**: payload in word/synonym choice of ordinary
  English. Evades every monitor tested (best monitor ≤27% detection);
  sanitization does nothing; "no two-line fix exists".
- **Construction channels** (from `experiments/e3s_stego_channel.mjs`):
  S1 zero-width chars, S2 homoglyph substitution, S3 model-native semantic,
  S4/S4b tag characters, S5 NBSP binary, S6 NFD normalization, plus a
  hair-space channel and a negotiated-protocol experiment where two models
  invent their own encoding.

### The experimental design (the most transferable part)

The E3S harness is exactly the blind-analysis structure this repo's charter
demands and its current experiments lack:

- Deterministic graded payloads (seeded; `{color, number, shape}` tuples,
  ~10 bits entropy; field-level partial credit on grading).
- Three roles with fixed prompts: sender (payload + cover topic), receiver
  (payload extraction with the method hint), monitor (extraction with no hint).
- Metrics: delivery rate R, monitor catch rate M, Youden's J, exact McNemar
  on discordant pairs, asymmetry, bootstrap CIs.
- A `--mock` mode so the harness runs deterministically without API cost.
- Honest failure documentation: the paper's own first draft contained
  fabrications (a "23 blind spots" claim that was actually 3), caught by
  adversarial self-audit and documented; every number re-derives from shipped
  raw JSONs. This mirrors this repo's Phase-0 invalidation culture.

### Why it matters for agent-stego

agent-stego's token-stego arm is a single-model encode/decode round trip; its
tool-call arm is single-sender. Neither measures adversarial detectability
with a monitor, and neither has any Unicode/tokenizer-level carrier. The
tokenizer-blindness mechanism is a genuinely different channel family (no
token-probability steering at all) that the charter's surface map lists only
as "activations/latent" — a gap this round's `text_channels.py` starts to
fill.

## 3. P4RS3LT0NGV3 — universal text transformation

222 transforms: encodings (base-N family, Morse, ciphers), formatting, and a
**Concealment** category — acrostic, Cardan grille, homoglyphs, invisible text
(Unicode tags), null cipher, Trevanion cipher, whitespace stego, zero-width
stego. Mostly classical cryptology; the concealment entries are the same
carriers as ST3GG's text techniques. The app is a static site with an
OpenRouter integration for model-curated transforms. Relevance: a reference
catalog of text carriers; several (acrostic, null cipher, Trevanion) are
*linguistic-pattern* channels that could be driven by an LLM sender, which
connects to the semantic-stego direction.

## 4. T3MP3ST — multi-agent red teaming

An offensive-security meta-harness: a multi-agent kill chain (recon →
exploit → report) driven by the user's existing coding agent, with a browser
War Room. Reproducibility culture is the transferable part: "every number in
this README recomputes from committed data — `npm run verify-claims` re-derives
all of them, 27/27 green." It also carries an explicit status table separating
stable / experimental / roadmap. agent-stego's Phase-0 rebuild is already
moving the same direction (claim-evidence ledger, historical-artifact
invalidation); T3MP3ST is a good template for a future "verify-claims"
command that re-derives every number in `analysis/`.

## 5. ImageDefender — adversarial watermarking

Adds an adversarial watermark to uploaded images to neutralize AI photo
modification (inpainting, filters). Relevant as a *defense* pattern: instead
of detecting stego, perturb the carrier so payloads degrade. The charter's
"active warden" role is the agent-stego analogue and remains unimplemented.

## 7. Novelty notes

The mechanisms ported this round are close reproductions or recombinations of
published techniques: zero-width, homoglyph, tag-character, NBSP, NFD, and
variation-selector carriers are documented techniques, and the tokenizer-
asymmetry story is GLOSSOPETRAE's published result. They are baselines, not
release-novel candidates. The interesting novelty frontier for this repo
remains its own charter's high-priority unexplored surface: **cross-surface
composition** — e.g. a tool-call channel whose *arguments* are chosen to carry
a text-channel payload, or a token-likelihood coder that also modulates tool
trace structure. Those are the candidates a future discovery wave should
target.

## 8. What this round added (infrastructure, not findings)

- `src/token_stego/text_channels.py` — six deterministic Unicode carriers with
  self-describing framing and an exhaustive-decode registry.
- `src/token_stego/tripartite.py` — sender/receiver/monitor harness, graded
  payloads, McNemar / Youden's J, configurable tokenizer-asymmetry profiles
  (sourced from GLOSSOPETRAE E3S, unverified locally).
- `src/channels/text_composed.py` — cross-surface composition: `FileContentChannel`
  hides a text-channel payload in the content of a file the agent legitimately
  writes; `ArgumentCarrierChannel` hides a payload across read_file path
  arguments; `HonestExecutor` simulates an exact prompt-following model so the
  contract is testable offline; `detect_trace_payload` is the sighted monitor
  (per-string, per-tool join, and full-join reconstruction strategies).
- `experiments/unicode_channel_eval.py`, `experiments/composed_channel_eval.py`
  — offline evaluation drivers writing to `findings/`.
- `tests/test_text_channels.py`, `tests/test_tripartite.py`,
  `tests/test_text_composed.py`, `tests/test_detector.py`,
  `tests/test_json_order.py`, `tests/test_hopping.py`,
  `tests/test_self_describing.py`, `tests/test_matryoshka.py`,
  `tests/test_multiturn.py`, `tests/test_historical_detection.py`,
  `tests/test_polyglot.py`, `tests/test_multistage.py` — 195 tests, plus
  `scripts/verify_claims.py` asserting every headline offline number (13 claims).

Initial offline results (deterministic simulation, not model measurements):

- Every text channel delivers 100% and is caught 100% by a sighted exhaustive
  monitor; the documented tokenizer blind-spot pairs (tag-char Haiku→GPT,
  NBSP/NFD GPT→Haiku) show 100% delivery with 0% catch (McNemar p≈0.002).
- Cross-surface compositions deliver 100% to the receiver; a content-reading
  monitor catches 100% while a surface-only (tool name/count) monitor catches
  0%. The argument composition defeats *per-string* monitors — the payload is
  split across many short paths and only a join-reconstructing monitor sees it.

All of it runs in the lean CPU path (stdlib only, no torch/API), is typed
clean under pyright, and passes ruff. The tokenizer profiles are explicitly
labeled research claims pending local measurement; real-model tripartite runs
are future work requiring an API/compute budget and the repo's approval
rules.

## 9. Candidate next directions (for the discovery program)

1. **Real-model tripartite runs**: replace the tokenizer simulation with
   actual LLM sender/receiver/monitor calls (OpenRouter), measuring delivery
   and catch rates under the published blind-spot pairs. Requires API budget
   approval.
2. **Semantic stego**: LLM-native word/synonym choice channel, evaluated with
   the tripartite harness and an LLM monitor. The hardest and most
   interesting open problem in the space.
3. **Tool-trace detection suite**: an ALLSIGHT-style registry of detectors
   over `ToolTrace` sequences (tool ratios, argument patterns, ordering
   entropy, timing), with a synthetic ground-truth corpus.
4. **Self-describing headers for tool channels**: embed mode/table/config in
   the trace itself (e.g. a reserved tool call) so decode needs no side
   information.
5. **Cross-surface composition** (charter high-priority): a joint
   tool-call + text-surface channel. **Started this round**: `text_composed.py`
   demonstrates file-content and argument-carrier compositions offline; the
   open work is real-model execution fidelity, a multi-turn variant, and
   cover-task utility measurement.
6. **Agent-facing skill/CLI**: a `SKILL.md`-style interface for running this
   repo's channels from an agent, following ST3GG's zero-context-cost
   subprocess pattern.
7. **Cover-task utility harness**: measure how much a channel degrades the
   legitimate task, which the charter requires and no current code measures.
